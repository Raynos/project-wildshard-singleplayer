# E32

**Status:** done (2026-09-25) — fixed by E130 D (`c2fe91a`, live build 5de4ef9-mugvhywt): Esc is the menu's own key now (one listener in src/ui/Menu.ts), the HUD's nolock Esc listener is gone; checked headless: Esc opens Settings and stays, Esc again closes
**Ask:** (found by the feedback-inbox session) In ?nolock dev mode Escape opens the pause menu and closes it in the same keypress

Cause: the HUD's keydown handler (`src/ui/HUD.ts`, "Escape on devices without pointer lock") calls `setPaused(true)`,
which opens the menu. The same keydown then reaches the menu's own document listener (`src/ui/Menu.ts` constructor,
`if (e.code === 'Escape') … this.close()`), which was registered later, so it sees the menu open and closes it.
Reproduced headless on 1ee4d74 with `?skipintro&nolock`: after Escape, `hud.paused` stays false. M opens the menu fine.
Fix idea: in the HUD handler, `e.stopImmediatePropagation()` after opening, or let the menu ignore the Escape that
opened it.
