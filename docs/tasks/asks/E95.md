# E95

**Status:** done (2026-09-24) — `70c28ac`, live in `8f8bb9e-muffx988`

Cause: coming back to the app, the pill's version.json poll lit "new build · tap to update" while the new service worker
was still installing. A tap then took the `?v=` network reload, which already loads the new build, under the old worker.
The new worker finished installing, went to `waiting`, and announced itself, so the pill lit up again for the build
already on screen. The second tap adopted it and reloaded again.
Fix: `src/boot/sw.ts announce()` asks the waiting worker for its build (new `BUILD` message in `src/pwa/sw.js`). If
the page already runs that build, it sends SKIP_WAITING quietly: no pill, no reload.
Verified locally (two builds swapped under one page, Playwright): after the `?v=` reload the pill stays dark and the new
worker takes control; a page still on the old build lights the pill as before.
**Ask:** Tap to update has to be pressed twice: new build available → tap → loading screen → new build available again → tap → loading screen again
