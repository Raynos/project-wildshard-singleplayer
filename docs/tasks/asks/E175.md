# E175

**Status:** done (2026-09-25) — commit below, build id recorded after the deploy.
**Ask:** The little settings button at the bottom is still way too close to the bottom of the screen. All of this UI stuff needs to go up another 20 pixels, so there's extra space between the bottom of the screen and the settings button — it's too close to the iOS app switcher.


## What it was

`index.html` deliberately has **no `viewport-fit=cover`** (E58), so on Jake's home-screen PWA
`env(safe-area-inset-bottom)` resolves to **0** — the `+ 26px / + 20px` that E146 added to
`.ws-menu-deck`'s `padding-bottom` was the *whole* clearance, not a bonus on top of a 34 px inset.
Measured on an iPhone 16 Pro viewport (402×874, inset 0): SETTINGS' box bottom sat **20 px** off the
screen edge and DEV's tap target (it has `margin: -10px 0`) reached **10 px** — right under the iOS
app-switcher / home-swipe strip.

## The fix

`src/ui/styles/menu.css` — the deck's bottom padding, +20 px on both phone rules. One padding on
`.ws-menu-deck` lifts the whole lower block (cards, dots, ENTER WORLD, SETTINGS / SOUND / DEV) together,
which is what Jake asked for ("all of this stuff").

- phone portrait (`max-width: 700px`): `env(...) + 20px` → **`+ 40px`**
- phone landscape (`orientation: landscape and max-height: 500px`): `+ 14px` → **`+ 34px`**, and the
  card-height budget in the same rule `100vh - 235px` → **`- 255px`**, so the extra 20 px comes out of
  the card image instead of pushing ENTER WORLD off a ~402 px-tall landscape screen.
- desktop base (26 px) left alone: no app switcher there.

Measured after (same viewport): SETTINGS **40 px**, DEV's tap target **30 px**.
