# E338

**Status:** open (2026-09-30)
**Ask:** Lane tooling bugs found in the E264 Simulator check: sim-lane.sh run leaves its --max timer's sleep orphaned (holds a piped caller open until --max); serve-build.sh stop all-mine matches other agents' servers (it keys on the caller's cwd, shared by every agent in the repo root or a shared scratchpad)

Found 2026-09-30 while running the E264 Simulator check (scripts/nine-sim-memory.mjs). Owners: E316 (sim-lane.sh) and
E317 (serve-build.sh), both done, so the bugs are queued here.

1. **`scripts/sim-lane.sh run` orphans its `--max` timer's `sleep`.** The `run` branch starts
   `( sleep $((max * 60)); … ) & timer=$!`. At the end it runs `kill "$timer"; pkill -P "$timer"`, in that order. Killing
   the subshell first reparents its `sleep` to launchd, so the `pkill -P` finds nothing. The `sleep <max×60>` lives on
   and holds the caller's stdout. A `sim-lane.sh run … | tail` therefore does not return until `--max` runs out.
   On 2026-09-30 there were ~10 orphaned `sleep 1200` / `sleep 2400` with ppid 1.
   - Fix: `pkill -P "$timer"` before `kill "$timer"`, or `exec sleep` inside the subshell.
2. **`scripts/serve-build.sh stop all-mine` stops other agents' servers.** "Mine" means the registry's `cwd` equals the
   caller's `$PWD`. Every agent that runs it from the repo root, or from a scratchpad that sibling agents share, owns
   every server started there. The E264 comparison build's server was stopped 44 s into a measured run.
   - Fix: key the registry row on the session instead of the cwd, e.g. the caller's session id / `$CLAUDE_SESSION_ID`,
     or the parent shell's pid tree.
- 2026-09-30 evidence for bug 2: the E264 memory pass's two preview servers (a baseline and a cut) were each evicted
  1–2 min after start by other agents' `serve-build.sh` calls. With the lane at 8, the eviction picks the caller's own
  oldest server, and every agent's cwd is the repo root. The A/B that ran against them was void.
