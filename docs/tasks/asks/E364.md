## API gaps (round 2)

Every gameplay need was met by a documented API (structures + registry pieces, `app.player.mode` in a piece's
`active()`, `flight: { above: 'world' }` + `ctx.flight.steer`, `animal.impulse`, `world.killY`, an open `style`,
`horizon: { rings: [], cloudSea: false }`, `touch.relabel.r0`, `keysFrom`, `equipmentHost.viewmodel`). Gaps:

1. *A custom rig's required bones are undocumented.* The first phone boot failed at `level.play`: `animal 'driftRay':
   rig has no bone 'head'`. `Animal` requires bones named `body` and `head` on every rig (`rig: 'custom'` included);
   ENGINE.md §19 / SHARDS.md §6 describe `rigContract` (skeleton, sockets, clips) and `build()` bones but never say
   that. Found from the thrown message only (the template's blob happens to have both). Fixed in the shard by adding a
   `head` bone at the ray's snout. Wanted: §19 states the required bones (or the look row validates its contract at
   `ctx.rows.speciesLook` time, in the contract test, instead of at the first spawn on a device).

## API gaps (round 3)

1. *An asset-free shard cannot omit `audio.preload`.* ENGINE §15 ("An asset-free shard can omit `preload` as well") and
   SHARDS §8 say `preload` is optional when a shard ships no music or SFX. The first phone parity boot of `1a511446`
   failed at `level.data`: `far-reach: boot audio requires the authored preload profile` (`startAudioPreload` in the
   engine boot always demands a `LevelAudioProfile`). Fixed in the shard with the documented type: `audio/profile.ts`
   returns an empty `LevelAudioProfile` (no files, empty banks), wired as `preload`. Wanted: either the boot accepts a
   missing profile (no audio files, empty banks), or the docs say every shard supplies one and show the empty profile.

Every other need was met by a documented API: `ground.structures` + registry pieces (hull island tops, box
decks), a hover deck's `active: () => app.player?.mode === 'board'` (ENGINE §5, §14), `world.killY`, `horizon: { rings:
[], cloudSea: true }`, `boundary: { visible: false }`, an open `style` (`skyReach`), `flight: { above: 'world' }` +
`ctx.flight.steer`, a `sphere` strike with `motion.track: 'lead'`, `animal.impulse` for GUST, `body` + `head` bones,
`touch.relabel.r0` + a `verb.1` verb, `keysFrom: 'weapon.melee'`, `equipmentHost.viewmodel`, the backdrop's `clouds`
dome, `audio.ambience: 'none'`.

## API gaps (round 4)

1. *The `touch.relabel` value shape is undocumented.* ENGINE §10 says `touch.relabel.r0` labels the attack disc and that
   "`tone` / `accent` dress LOCK / JUMP; the attack disc keeps its existing charge/ready appearance", but never shows the
   value. `{ label: 'SWING', icon: '' }` fails tsc: `TouchRelabel` is `{ label, icon?, tone: 'rest' | 'ready' | 'active',
   accent? }` with `tone` required, even for `r0` where the docs say it is ignored. Used `tone: 'rest'`. Wanted: §10 shows
   the `TouchRelabel` shape (and says which `tone` to pass for `r0`), or `tone` becomes optional.
2. *A structures-only world doesn't boot.* ENGINE §6 says `ground` is "`{ terrain?, structures?, paths?, water? }`, at
   least one of terrain / structures", SHARDS §3 says "`ground.structures: true` for a built world", and §5a's
   `needsTerrainCollider` implies a level without terrain. The first phone parity boot of `c07a59fa` (`ground:
   { structures: true, paths: 'plugin' }`, no terrain) failed: `boot.errors` `["No terrain for far-reach"]` (thrown by
   `terrainFor` in `src/game/shard/manifest.ts` / `terrainOf` in `src/engine/world/Heightfield.ts`; some boot consumer
   still requires an analytic terrain). Carried on with the documented "or both": a flat `buildTerrain` far under the
   void (`landscape: () => VOID_Y`, y −40: `test/chunks.test.ts` wants every height above −60; one trail from the spawn) beside `structures: true`, so it gets no collider, and a
   `terrainPainter` that draws nothing. Wanted: a structures-only `ground` boots (consumers fall back to registry
   floors), or the docs say every shard needs `ground.terrain` and show the stand-in.
