**Status:** in flight (2026-11-07, Codex; built and proved, awaiting scheduled push)
**Ask:** Jake on his real iPhone: dying in Driftwood no longer shows anything, it just respawns him on the pier; there used to be a death screen. Reproduce on a real page, then deliver the server own-player death to page player.died exactly once with checkpoint and cause. Sweep every page listener and check respawn ordering so the overlay shows before moving. No Three.js or layout change. Prove worker-client-play on Chromium and WebKit.

**Reproduction:** A real Driftwood bear killed the worker player in Chromium (health 100 → 55 → 10, then one server fall). The page returned to the pier with zero `player.died` events, no overlay class, empty cause/destination text, an open wire and no page errors.

**Listener sweep:** These are all seven page subscriptions. Before the flip, page `PlayerHealth.update` emitted `player.died` after resolving `death.checkpoint`. Since the flip, the worker owns damage and the page mirrors HP with a floor of one; its incoming damage cap is zero. The old bridge only played death audio and a damage flash. None of these subscriptions heard the worker death; conditional listeners were affected whenever their corresponding service was installed.

**Authority and ordering:** `PlayerHealth.update` restores server health and resolves the server checkpoint before emitting the lifecycle event. `installRoomRespawn` starts the 1.8-second invulnerable return and immediately resets a normal death to the server's last place/spawn; a checkpoint death belongs to its boss. The new reliable owner-only lifecycle event is distinct from `actor.died`/ragdolls and carries the settled checkpoint and complete optional cause. The client rejects other owners and repeated/older ticks. The worker holds page prediction/reconciliation before enqueueing the page event. At the existing fade's dark callback the page adopts the latest authoritative pose, without sending a second local spawn. A checkpoint that skips the ordinary fade releases the pose immediately. Server simulation, UI layout and Three.js presentation remain unchanged.

**Proof:** Both Chromium and WebKit pass `worker-client-proof.mjs --play --only=death` (3/3 each), muted with the iPhone 16 Pro profile. Each real bear kill produces exactly one own-actor page event with `checkpoint: false` and `{ kind: 'bear', label: 'Brown bear' }`. The existing card shows “Mauled by a brown bear”; its fade reaches dark before the page moves over 100 m to the pier, then finishes with page/server positions matching and no page errors. The existing destination copy says “respawning at the south gate” on this build; the wire repair leaves that copy untouched. All 25 focused death/wire/motion/respawn/declaration tests pass. Three new integration cases each complete under ten seconds and cover server checkpoints, complete/absent causes, duplicate reliable packets, later deaths, peer deaths, owner-only wire delivery, and holding/adopting the authoritative pose. Touched TypeScript, typed lint and engine side/player ownership checks pass.
