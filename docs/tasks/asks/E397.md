# E397

**Status:** done (2026-10-02, lead): the default key fixed in src/engine/render/shaderPatches.ts; ships with the next deploy
**Ask:** [from sky-reach] ENGINE TRAP: shaderPatches.ts keys a material's program by the LAST patch's fn.toString() when no key is given; a scene-wide patch run over every material gives them all one key, so an earlier material-specific patch silently compiles into a shared, unpatched program. Other shards may be affected.


**Fix:** a material with two or more of the registry's patches and no explicit key now gets the joined source text of
every own patch as its default program key (it was the last patch's text only). A material with one patch keeps
exactly its old key, so most programs are untouched. Test: test/engine/shader-patches.test.ts.

**Blast radius, measured** (all six shards, before vs after, scripts/shard-progress.mjs with the new `programs` field):
- Driftwood 97 → 97, Nine Dragon 68 → 68, Pine Hollow 111 → 111, Nalati 101 → 101, Signal Dunes 51 → 51 programs: unchanged
  keys, so unchanged rendering (the per-view pixel differences are animation noise).
- Sky Reach 59 → 74: fifteen materials with different patch code had been sharing one program. Its own workaround
  (def1c2b9) already covered the visible cases, so its hero views look the same; the rest now compile as written.
- An id-based key gave the same 74, which confirms they are real differences, not identical patches split apart.
