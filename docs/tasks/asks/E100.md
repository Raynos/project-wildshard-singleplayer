## Done
- **Comparisons:** `art/local-image/round-1-qwen21-vs-codex/`. 10 codex (left) vs local (right) JPEGs, with the same
  inputs and the same verbatim prompts; its README has a verdict per image.
- **Model:** `Qwen/Qwen-Image-2.1`, bf16, 33 GB, sha256-verified through `fetch-repo.sh`. Recorded in
  `~/projects/weights/MODELS.md` (weights commits `7911cd7`, `cce080e`, local, not pushed).
- **Runtime:** diffusers main `QwenImage21Pipeline` on MPS in `~/ml/imagegen/.venv` (torch 2.14, torchvision 0.29).
  mflux has no 2.1 edit mode yet.
- **Speed:** 84–132 s per image at about 1 MP and 40 steps; 57–63 GB of MPS memory; the model loads in 7–10 s.
- **Coordination:** every batch held the shared `~/projects/localai/.model.lock`, waited until anonymous memory was
  under 70 GB, stopped starting jobs after 25 min, and ran **no** `evict.sh`. The other agents' MOSS, TRELLIS and
  MiniMax queues kept running.
- **Trap:** one process running many jobs produced 8/10 black (NaN) frames. A fresh process per job plus an fp32 VAE
  gave 8/8 clean (`~/ml/imagegen/run_each.sh`).

## Verdict
- **Codex is still better at the mockup job.** It holds the input frame and Driftwood's toon palette.
- Qwen keeps the layout and large UI text, but garbles small text, drifts toward grey realism, turns the wooden sword
  to steel (4 of 6 frames that show it), and re-composes the camera when given several references.
- Qwen was closest on the desktop feedback sheet, the iPhone hover row, the photoreal Pine Hollow pond and the
  white-background asset reference.
- **The licence is research-only**, so it could never make shipped art. It is fine as an evaluation or internal
  sketch tool.
