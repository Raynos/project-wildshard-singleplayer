## What was wrong

Nalati ran its own phone HUD, **layout D** (NALATI-MERGE H2, `src/ui/NalatiHUD.ts` + `nalati-hud.css`): a `#hud.nalati-d`
class switched ~58 CSS rules across 7 stylesheets, so every base change (E119's LOCK · DODGE · JUMP row, E152 …) had to
be written with a `:not(.nalati-d)` guard and Nalati never got it. Its extras (STEED, HIDDEN, GRASS, CROUCH, GALLOP,
HORSE, OFFER, LEAN) each found the touch layer on their own (polling / MutationObservers) and placed themselves by pixel
offsets; the ✎ NOTE and JOURNAL tags sat at hard-coded `top:` offsets; the weapon strip was built in two places.

## What it is now: one base HUD, shards plug into slots

- **The base** (every shard): TouchControls' layer — PAUSE, the top-left status column, the bar (MOVE · ATTACK · LOOK),
  the E119 row, HOVER on the left edge, USE — and HUD.ts's VITALS + held-weapon ammo strip. Layout D is deleted:
  `NalatiHUD.ts`, `nalati-hud.css` and every `#hud.nalati-d` rule are gone.
- **`src/ui/hudSlots.ts`** is the one way anything adds to the phone HUD:
  - `hudSlots.statusRow(el, ROW.x)` — a row of the status column (shared glass `.ws-touch-row`, ordered by `ROW`);
  - `hudSlots.pill(el, onTap)` — a tag under the rows (✎ NOTE, JOURNAL);
  - `hudSlots.disc({ cls, icon, label, spot, press, release })` — a control disc at a **named spot** the base places:
    `r0` JUMP's · `r1` DODGE's · `r2` LOCK's · `r3` the 4th · `aim` wherever AIM is · `up0` over JUMP (USE moves up) ·
    `lean-l` / `lean-r` · `edge-r`. The owner only toggles `.show` and colours its own class;
  - calls are queued until the layer mounts, so main.ts build order no longer matters.
- **A shard's switches are data**: `ChunkDef.hud = { weaponStrip?, dayBadge? }` (Pine Hollow: the strip; Nalati: the
  strip + the minimap's sun / moon badge, now `Minimap.showDayBadge`). The strip is built once in main.ts.
- **Nalati's pieces through the slots**: CROUCH `up0`, GALLOP `r0`, HORSE/DISMOUNT `edge-r`, OFFER `aim`, LEAN `lean-l/r`
  (RideHUD, stealth.ts); STEED, HIDDEN and GRASS are status rows. THROW / BRACE were already E119 row members.
