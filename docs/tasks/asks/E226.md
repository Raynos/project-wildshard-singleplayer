## Measured memory

`scripts/gpu-texmem.mjs` wraps actual Chromium Metal WebGL allocation calls at phone tier, after a short settle. Nine Dragon's phone KTX2 path: 52.6 MB textures + 59.3 MB render targets + 1.5 MB renderbuffers = **113.4 MB**. Driftwood's image baseline: 39.6 + 78.1 + 10.4 = **128.1 MB**. Nine's uncompressed image path after phone-atlas reductions was 83 + 59.3 + 1.5 = **143.8 MB**. The 42 MB atlas cut and KTX2 bring Nine's measured GPU allocation under Driftwood's. The in-page scene-texture estimate omits render targets and browser surfaces.

In an iOS 26.5 Simulator home-screen PWA *before these optimizations*, Nine reached gameplay once and did not crash. Its WebContent phys_footprint was 519 MB steady, 789 MB lifetime peak; GPU process 251 MB steady. In the same PWA process Driftwood settled at 402 MB WebContent and 198 MB GPU. Exiting Nine to the static selector dropped WebContent to 144 MB. Simulator macOS footprints are not an iPhone RAM limit. The simulator reproduced a long 8.4 s page pause during Nine's Props step, not the physical phone's jetsam/black screen. A later physical iPhone test is still required.

The traced Props spike was 1.8–2.9 seconds in `bakeSpill`, not a kit conversion. Numeric spatial keys, cached emitter constants, direct attribute reads and yielding every ~8k vertices cut the Playwright WebKit longest pause below Driftwood's. Phone sign, glyph and weapon decal atlases were halved per axis. KTX2 was baked for Nine's hook, leaf atlas, scroll and viewmodel maps. The selected shard can cache its own KTX2 files on phone, without downloading other shards in the background.
