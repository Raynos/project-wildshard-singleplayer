# E98

**Status:** needs you (2026-09-24) — `39a2c2b`, live in `39a2c2b-mufg9sdz`; Jake checks the app switch on the iPhone

Cause: the black blink was the RESUMING screen itself. It was dropped two frames after the first draw: fully up ~40 ms,
gone by ~170 ms (measured in Chromium), which on a 30 fps phone is one or two frames of near-black glass (`#070e16`
under a still dimmed to 50 %). The still was also only taken while the page was already hidden, where iOS may hand back
an undrawn (black) buffer.
Fix (`src/core/GpuRecovery.ts`, `src/ui/styles/resume.css`): the screen holds ≥ 500 ms after the page comes back, then
fades; the still is brighter (80 %); the still is also taken on window `blur`, before the page hides, and a blank still
never replaces a good one.
Verified: Chromium, fully up 540 ms then a 160 ms fade; the iOS 26.5 simulator, Safari → Settings → back
(progress/218-e98-resume-screen-ios-sim.jpg): the blurred game with RESUMING for about half a second, then the pause menu;
no black frame.
Open finding (not explained, not built): the baseline simulator switch on the live build before this fix
(`8f8bb9e`) showed neither the resume screen nor the pause menu after coming back. The HUD was still up, as if
`visibilitychange` → `ws:background` never reached the game. The same switch on the dev server afterwards paused into the
menu as designed. If the iPhone check shows no pause menu after a switch, start here: run
Safari → Settings → back in the iOS simulator (`xcrun simctl launch`) on the live build and log `visibilitychange`.
