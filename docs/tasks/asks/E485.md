**Ask:** I think we lost the really big hero art for each one of the shards in shard select. Can you figure out what happened to the really big hero art?

## What happened

Board: [`art/menu/round-13-hero-art/what-happened.jpg`](../../../art/menu/round-13-hero-art/what-happened.jpg)
(A before, B Jake's pick, C today, D a preview of the hero put back; iPhone 16 Pro portrait).

- **Where it used to show:** until 2026-10-04 the title deck filled the whole screen behind the card with the selected
  shard's own hero art (`.ws-menu-hero`, from each manifest's `card.portrait` / `card.landscape`; panel A, capture from
  build `71101c4a1`).
- **What replaced it:** `1ab84ccf7` (2026-10-04, SHARD-PLATFORM SF21a, "SHARD SELECT restyled to the new menu", G106).
  It added `.ws-menu.ws-menu-carousel .ws-menu-hero { background-image: url(<main-menu crossroads>) !important;
  filter: blur(6px) brightness(0.62) … }` in `src/game/mainMenu.css`. That rule overrides the per-shard image the deck
  still sets. `f6d5a04f9` (2026-10-12, G341) then swapped which crossroads image gets blurred (painted portrait → the
  in-engine L-b landscape aerial). That is the blurred picture across the top half.
- **Was it picked?** Yes, as part of a board. Jake picked **G106, "A Carousel restyled"** from
  `art/menu/round-8-shard-select/board.jpg` (ask E438, 2026-10-04). All three variants (A, B, C) put the dimmed and
  blurred crossroads behind the cards, so the board never asked "shard hero or crossroads". Choosing A also chose that
  backdrop, so this is a design he picked, not a broken path. Per the brief it is left unchanged.
- **The medium image in the card** is the shard's thumbnail (`card.thumb`, ~50 KB), not the hero. It was there before too.
- **Not a load failure, not a Debug row:** nothing is behind a Debug row. The hero files are all still in the repo
  (`src/shards/<slug>/thumbs/<slug>-portrait.jpg` / `-landscape.jpg`) and `titleDeck.ts` still sets them on
  `.ws-menu-hero` each time a card is selected. Only the CSS override hides them.
- **Wasted bytes:** `titleDeck.ts` still warms the neighbours' hero files on a swipe (`warm()`). Today nothing shows them.

## If Jake wants it back

Panel D shows today's restyled SHARD SELECT with the selected shard's own hero behind it, sharp and lightly dimmed. It
is a CSS override in the capture, not shipped. The fix is one CSS rule: drop the crossroads `!important` override (and
optionally the blur). Recommended pick for the coordinator to ask: **put each shard's hero back behind SHARD SELECT
(D)**, because it shows off the selected shard and the crossroads already fills the main menu.
