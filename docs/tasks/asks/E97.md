# E97

**Status:** done (2026-09-24) — `8c9a03f`, live in `8c9a03f-mufgddzo`; the user's own iPhone check of the pinch is the last word
**Ask:** As you zoom in on the main map, it gets blurry. Fully zoomed out it looks okay; as you zoom in it gets blurry. (pause menu MAP tab, iPhone) — follow-up: "I think the main map is stale as well … I can't tell."

**Cause:** the MAP tab stretched the minimap's one terrain bitmap (2 px/m, from heights sampled every 2 m) — at 4× on a 3× phone that is ~3.6× magnified, 6× → ~5.5×.
**Fix:** zoomed past 1.25× the layer, the full map paints 256 px tiles at the screen's own px/m over it (`Minimap.paintTile`, levels 4–32 px/m, ≤ 6 ms of new tiles a frame, 64 cached), heights Catmull-Rom interpolated off the 2 m grid so shores and cliffs stay smooth rather than stair-stepped; canvas DPR cap 2 → 3. 1× is unchanged. Before / after (iPhone 16 Pro, 4× top, 1× bottom): `progress/219-e97-map-zoom-sharp.jpg`.
**Stale?** No: the map is not a stored image — it is painted at load from the same heightfield you walk on, so it always matches the build. What it lacks is content: on Driftwood it draws only ground, sea and the pier — no hut, paths, palms, bridge — so it can read as out of date. Drawing those is not built (needs the user's go).
