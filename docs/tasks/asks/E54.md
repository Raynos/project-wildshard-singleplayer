# E54

**Status:** in flight (2026-09-23, iOS-lifecycle agent) — built and verified headless + iOS Simulator; deploying
**Ask:** iOS home-screen PWA: switching to other apps and back breaks the game — first garbage blue/orange polygons, then a frozen still frame of the spawn, and the game can't be played (WebGL context loss / restore?)

Jake's words: "There's a really bad glitch when you switch on iOS between various apps and switch back. First it looks
like blue and orange, like something is completely broken. Then it looks like a still frame from the spawn. But then
you can't play."

**Root cause (reproduced).** iOS drops a backgrounded app's WebKit GPU process. Killing that process reproduces it in
Playwright WebKit and in the iOS 26.5 Simulator's Safari against the live build:
1. The WebGL context is lost AND **every 2D canvas on the page is wiped** to transparent: the particle / sprite /
   smoke canvases the scene's textures are made from, and the minimap's painted terrain and fog of war (the minimap
   goes black). Probed: 9 of 9 scene canvas textures read back rgb 0 / alpha 0 after the kill.
2. three.js restores the WebGL context on its own (it already calls preventDefault). Its next `render()` then re-links
   every program **in one synchronous stall**. The boot splits that into batches because one stall takes 10 s to
   minutes on an iPhone (src/boot/precompile.ts), and nothing split it here: the main thread freezes on the last
   frame. That is the "still frame from the spawn, can't play". The garbage frame before it is the lost drawing
   buffer / blank textures being shown.
3. Only the native shells and the rotate page sent `ws:background`, so the PWA / Safari tab never paused on hide. The
   world ran straight on after the switch.
   On the Mac the stall is short (fast GPU), so headless runs only show the wiped canvases. The freeze length on a
   real iPhone comes from the precompile measurements, not from this run.

**What landed.**
- `src/core/GpuRecovery.ts` (new):
  - **Hide** (`visibilitychange` / `pagehide`): `ws:background` pauses into the menu (PWA and Safari too now), and the
    canvas is hidden until a healthy frame is drawn, so a broken buffer is never shown.
  - **Lost:** `preventDefault()`, then the frame loop holds (no tick, no draw, not even the forced frame), and a
    full-screen "RESTORING GRAPHICS" page comes up (navy glass, cyan hairline, `src/ui/styles/gpu.css`).
  - **Restored with the canvases intact** (a sentinel canvas still holds its colour: a plain context loss): restore
    in place. Every program is re-linked in batches with a progress bar (`game.precompile`, the boot's own step).
    The sky's PMREM environment is re-rendered (`Sky.rebuildEnvironment`), then the first frames are drawn. The game
    resumes under the pause menu.
  - **Restored with the canvases wiped** (the GPU process died: the iOS case), or a runtime bake in the scene
    (`src/core/gpuOnly.ts`, marked by TreeFactory's impostor / branch-card bakes), or a restore that fails or runs
    past 40 visible seconds, or still lost after 5 visible seconds, or no frame within 4 s after a restore: **reload**.
    Saves are already written through to localStorage on every change. The reload adds `?at=x,y,z,yaw,pitch`, so
    the player comes back where they stood; main.ts strips `at` / `glreload` from the address afterwards. More than
    2 automatic reloads in 2 minutes stop the loop: the page shows a RELOAD button instead.
- `src/core/Game.ts`: `hold` (the loop gate that beats the forced frame) and `kickLoop()`. On show, `kickLoop()`
  restarts the rAF loop if it has not run for 1 s. A duplicate chain ends itself on the shared frame timestamp
  (checked: 60 updates/s before and after a forced second chain).
- `scripts/e54-gpu-recovery.mjs`: the drill. Chromium `WEBGL_lose_context` in-place restore + hide / show + move / look.
  WebKit GPU-process kill → reload at the same spot. Exit code = failures.

**Verified (not on a real iPhone):**
- Chromium, `loseContext` → `restoreContext`: restoring page → restored in place in ~150 ms → pause menu → RESUME → moved
  6.5 m and turned. Hide → paused + canvas hidden; show → canvas back, drawing. (progress/199-e54-context-restore-chrome.jpg)
- Playwright WebKit, GPU process SIGKILL: live build = the minimap goes black and the canvas textures are blank.
  Fixed build = "RESTORING GRAPHICS · RELOADING", back at the same x/z/yaw, minimap intact, address cleaned.
  (progress/200-e54-gpu-process-kill-webkit.jpg)
- iOS 26.5 Simulator, Mobile Safari tab, the sim's `com.apple.WebKit.GPU` killed: live = "gl lost ×1 restored 21 ms",
  black minimap; fixed = reloading at +1 s, back in play at +3 s, minimap intact at +40 s.
  (progress/201-e54-gpu-process-kill-ios-sim.jpg)
- Not verified: a real iPhone, the home-screen (standalone) PWA, and how long the freeze was on real hardware.
