## Jake's context (2026-09-30, verbatim in substance)

- The four shards are generic shards bolted on top of a base game. There is a **base, flexible game engine with
  interfaces**, and anyone (Jake included) can implement a new shard on top of it: a fifth, sixth, seventh.
- A shard is **a directory that implements an interface**, like a plugin. "Almost dynamically loaded", except it isn't,
  for performance, baking and optimization reasons.
- Code shared among shards that doesn't belong in the base engine goes into **a shared library** among shards.
- Any shard `if` in `main.ts` is bad. The base game is generic: it boots and goes directly into whatever makes sense.
- Move as much code as possible out of shard-specific places into the shared baseline (the custom Wildshard engine /
  game logic), and push everything shard-specific into that shard's directory.
- **No other agents work in the repo during the normalization: this session has a lock on the whole repository.**
