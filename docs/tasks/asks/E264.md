**A regression check, not phone evidence.** The Simulator runs on the Mac's memory and GPU. The phone killed WebContent at
multi-GB while the Simulator stayed under 1 GB (E271 / E272). Nothing here says whether the phone now meets the caps.
Only a physical reading can say that.

Setup: iPhone 17 Pro Simulator (`wildshard-iphone`, iOS 26.5, Safari; DPR 3, canvas 804 × 1428), through
`scripts/sim-lane.sh run`, and shut down after. Each run had a cold Safari relaunch. The builds were clean `git archive`

## 2026-09-30 memory cut pass: handoff (to the render agent)

The Simulator driver is on main (`ec29c499`, `scripts/nine-sim-memory.mjs`).
- **Today's baseline:** Explorer native ~0.49 GB, Inspector 0.745–0.769 GB (`d82c6cc9`, `7a73e6aa`).
- **The command:** `node scripts/nine-sim-memory.mjs --rev=HEAD --rev=<cut commit> --runs=2`, about 12 min. It serves both
  revs, runs the lane, prints the table and stops its servers.
- **Serve-lane caveat:** the 8-preview lane is full, so another agent's `serve-build.sh` evicts yours within minutes
  (E338 bug 2). Check each run's build id in the table's log, and re-run if the server was replaced.

What the World Explorer holds (Simulator, HEAD `8b2ce8a2`, after `Heap.gc`):
- **Total:** Inspector 745 MB, of which JavaScript 466, page 157, other 98, jit 16, images 7.
- **Geometry arrays in the scene:** 154 MB, of which 4 MB are instanced.

The cuts and findings, largest first:

1. **The fabric's static geometry: −104 MB JS measured, not shipped.**
   - *What it is:* every attribute but `position` of the kits, the facade shell and the canopy. The positions and the
     index stay for the Explorer's tap picking (`pick.ts` raycasts the kits that models are drawn into). The bounds
     are computed first.
   - *Measured:* releasing those arrays live in the page (after upload) took Inspector 745 → 641 MB, JavaScript
     466 → 362 MB. The frame looked unchanged, as it must: the GPU buffers are untouched.
   - *The code:* parked on the local ref `refs/wip/e264-cut1` (`0a704afa`, not on main). It adds `gpuOnlyAttributes()`
     in src/core/gpuOnly.ts (`onUpload` → a zero-length array, plus `markGpuOnly`, so a lost context reloads the page)
     and wires it in world/build.ts at 'world ready'.
   - *Not verified:* its one A/B was void, because both preview servers were evicted mid-run. The tab that was
     probed still held `onUploadCallback(){}` on `kit:stair-terraces`: either it was someone else's build, or the
     kits upload before 'world ready'.
   - *To do:* set the hook where each kit mesh is made (`kitMesh()`), on the canopy before `root.add`, and on the facade
     shell before `root.add(facade.group)`. Confirm that `kit:stair-terraces`' `aFace.array.length` is 0 after the
     first frames. Then run the frozen frames and the driver.
2. **Audio: 141 MB of decoded AudioBuffers, 30 % of the JS heap. Not built, and it is the audio owner's file.**
   - *The duplicate:* Nine Dragon's `pine` calm (23.6 MB) and tension (11.8 MB) are decoded twice. `Music.useBank`
     merges `new Map([...old.slots, ...bank.slots])`, so the new copy replaces the one the deck plays. With the old
     entries winning, the duplicate is dropped: −35 MB, identical audio.
   - *Also held:*
     - the title's calm, 23.9 MB, after the title;
     - the `forest` (10.7 MB) and `underwater` (8.4 MB) beds;
     - ~15 MB of other shards' shots (animals, rifle, water);
     - the Karplus–Strong synth's buffers, ~5 MB.
3. **Canvases and bitmaps kept after upload:** 17 MB of canvases (one of 8.4 MB) and two 4.2 MB ImageBitmaps.
4. **Smaller or already handled:**
   - the hidden viewmodel's skinned meshes under the camera, 12 MB;
   - `facade/batch.ts` bakeCache, already freed by another agent's (then uncommitted) E323 hunk.
5. **Not attributed:** ~150 MB of JavaScript. JSC's heap snapshot does not size big typed-array backing stores or
   Rapier's WASM heap. A V8 heap snapshot in Chromium would show them, with retainers.

**The frozen-frame check** (at the four mockup cameras, in the page):
1. Set `game.clock.getDelta = () => 0; game.clock.elapsedTime = 100`.
2. Hide `camera.children`.
3. Pose the camera from `MOCKUP_CAMERAS` in an `onLate` hook (`rotation.set(pitch, -yaw, 0, 'YXZ')`), with
   `freeCamera = true`.
4. Take `game.captureFrame(10000)`, then `toDataURL('image/png')` (poll the result: WebKit's `Runtime.evaluate` does not
   await promises).

Two captures of the same build give the noise floor.

## The cut pass (2026-09-30, the render lane)

Each cut is its own commit and pixel-identical: frozen frames at the four mockup cameras differ by 0 pixels, and two
captures of the base agree exactly.

| Cut | Commit | What goes |
|---|---|---|
| 1 | `d1cdcee3` | The city kits, facade shell and canopy keep only positions and the index in JS once uploaded (`gpuOnlyAttributes`, set where each mesh is made). JS geometry 154 → 51 MB. |
| 2 | `ab60af75` | `Music.useBank` keeps the copy already playing: Nine Dragon's two music stems are no longer decoded twice. Same sound. |
| 3 | `85a2b834` | Texture sources released after upload: the paint array, the Fei Zhua hook's two 1024² maps, the sign atlas canvases and the mono copy. About 30 MB. |
| 4 | `8166e740` | Light volumes and the sky-scroll image: JS textures 8 → 2 MB (inside the Simulator's noise). |

| Build | Loading (cap 1.8) | Play | World Explorer (cap 1.0) |
|---|---|---|---|
| Base | 0.725 / 0.851 | 0.505 / 0.848 | 0.502 / 0.767 |
| Cuts 1–3 | 0.718 / 0.776 | 0.384 / 0.671 | 0.366 / 0.598 |
| Cuts 1–4 (separate run) | 0.726 / 0.822 | 0.466 / 0.762 | 0.394 / 0.617 |

- **A lost context:** with cuts 1 and 3, a lost WebGL context on Nine Dragon reloads the page instead of restoring in
  place. On iOS the canvases are wiped on a loss anyway, which already reloaded (GpuRecovery.ts, E54). The reload
  lands where the player stood.
- **Not cut, and why:**
  - The title music (23.9 MB): EXIT TO MAIN plays it at once, so a lazy decode would play the synth fallback instead.
  - Sounds Nine Dragon never plays (the underwater bed 8.4 MB, other shards' one-shots ~15 MB): these need a per-shard
    filter in `audio/preload.ts` and `boot/extras.ts`, checked against every sound Nine Dragon triggers. The audio
    owner's call.
  - The viewmodel arms (~12 MB), the leaf atlas and the glyph SDF: possible. The arms are the riskiest, because the
    skinned mesh bounds read those arrays. They belong to the viewmodel lane.
- **Same bug found:** the grapple rope's pulse and the hook ring had E337's `pow(negative, 2.0)` bug too. Fixed in
  `db071c72`.
