## Physical isolation and default fix

Safari build `e5e8b8e-muloh54x`, `nineFacade=instanced`, lanterns on: Nine Dragon loaded, entered World Explorer, and rendered for over 90 seconds without another native kill. Inspector observed load peak ~746 MiB (0.782 GB), Explorer peak ~1005 MiB (1.054 GB), then garbage collection reduced it to ~0.69 GB. This succeeds at reproducing a working path but does NOT meet the strict 1 GB Explorer cap.

Chrome's default facade path independently failed on the connected phone: 15:13:17 WebContent PID79224 killed at 3,969,601 KB; retry PID79272 killed at 15:13:30 at 2,256,961 KB with ActiveHard2048MB. Inspector sampling only observed ~684 MiB before the native spike. Source-level root allocation remains unproven; evidence isolates the facade multi-draw path, not a JS leak or a measured VRAM total.

Wrap-up change forces the retained instanced facade path on MOBILE_DEVICE (actual mobile UA or phone tier), even with stored Auto or forced desktop quality. Desktop Auto retains multi-draw. Red paper lanterns remain enabled by default. Clean-export validation, deployment, then repeated default-setting physical acceptance are required.
