# E261

**Status:** in flight (2026-09-28, Codex simulator_memory_watchdog)
**Ask:** Have a subagent build the test watchdog on the Simulator and fail above the memory budget

Implemented `scripts/ios-memory-watchdog.py`: native macOS physical footprint and
RSS, default 4 GiB budget, sampled Simulator-scoped process identities, nonzero on
budget breach, process replacement/disappearance, sampling errors or empty runs.
Usage and limitations: [Simulator watchdog](../../ios-memory-watchdog.md).
Validation: three regression tests pass, including a real 64 MiB owned subprocess
allocation crossing its native budget. Actual iOS 26.5 Simulator smoke recorded
824,563,928 bytes peak aggregate footprint and passed a 4 GiB budget; the same
Simulator correctly failed a deliberately tiny 0.001 GiB budget (exit 1). Missing
PID timed out with exit 2; shutting down the owned Simulator failed on tracked
process disappearance (exit 1). This verifies enforcement, not a shard baseline.
All test processes and the owned Simulator are stopped. Reports are local under
`/tmp/e261-simulator-*.jsonl`; raw process reports are not committed.

Commit, clean-export gate and deploy evidence pending.
