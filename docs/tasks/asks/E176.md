# E176

**Status:** done (2026-09-25) — `105c090b`, live as `bcf12c4-muhuqijs` (it shipped inside E162's push).
**Ask:** The in game PAUSE menu in level, should have the update pill there. we need to redo this UI to make space for the update pill, it should have same location as main menu.


## What it was

The build pill (`src/ui/Update.ts`) is the only way a home-screen PWA can pull a new deploy — there is no address
bar. It showed **only on the loading / title screen** (`onTitle && (newer || isDev())`), at `z-index: 60`. The menu
overlay is `z-index: 70`, so even on the title screen the pill was *behind* main menu ▸ Settings. In the world there
was no way to it at all without exiting to the main menu.

## The fix

- **`src/ui/Update.ts`** — visible on the title **or** while the pause menu is up (`.ws-gmenu.show.pause`), under the
  same E140 rule (a player sees it only when a newer build waits; developer mode always). It publishes `--ws-pill`
  (`24px` while it is up, `0px` otherwise) on `<html>`.
- **`src/ui/Menu.ts`** — the menu root carries `pause` when the PAUSE group is the one showing (never the BAG), and
  `open()` / `close()` / `syncTabs()` fire a `ws-menu` window event. Update.ts is a separate entry script
  (`index.html`), not a module anything imports, so the event is how it hears the menu open.
- **`src/ui/styles/update.css`** — `z-index: 60` → **`80`**, above the menu overlay. Position unchanged, so the pill is
  at the same screen corner in both menus (`right: 16px` phone / `44px` desktop, `top: 10px + safe-area`).
- **`src/ui/styles/gmenu.css`** — the space Jake asked for: the overlay's top padding is now
  `calc(var(--ws-top) + 4px + var(--ws-pill, 0px))`, so the sheet starts **below** the pill instead of under it. Nothing
  is reserved when the pill is down.

Measured on an iPhone 16 Pro viewport: pill top 10 px, bottom 29 px; sheet top 34 px — in both the pause menu and main
menu ▸ Settings. On resume the pill goes and `--ws-pill` is back to `0px`.
