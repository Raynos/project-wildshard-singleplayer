## §1 as written before G291 (the legacy-share measure)


Unit: non-blank, non-comment source lines of `.ts` / `.tsx` / `.as` under `src/shards/<slug>/`, counted by `scripts/shard-platform.mjs` with the matching parser (C2-R1-B11).
Generated and baked output never counts.

- **The split in Jake's words (G136):** *"80% hard code using the sdk and 20% custom runtime code with no shared kit
  dependency"*: the 80 % is shard code written against `@wildshard/sdk` (its public, MMO-compatible surface: rows, data,
  generators, AssemblyScript behaviour, quests); **TypeScript that ships in the game counts custom wherever it sits** (G146
  overrides G136's "in any folder": a shardfile carries only data and AS; C2-R3-C5); the 20 % is
  `runtime/`, trusted TypeScript that may use the SDK's trusted runtime surface but never a shared kit (G135 dissolves
  it); shared content comes from the **commons package** (G137) by reference.
- **Public side:** `generators/` **whatever they import** (they never ship: `wildshard/no-runtime-generator` and
  `check-chunks` enforce it; A2: any tool on the author's machine), and `data/`, `behaviour/` (AssemblyScript), `quests/`
  and `shard.config.ts` (build-time sources that compile to data or AS), when their import closure reaches only
  `@wildshard/sdk`'s **public surface** (the headless-safe modules; anything under `@wildshard/sdk/runtime/*` counts as
  custom wherever it is imported, so moving kit renderer code into the SDK can't inflate the 80 %; C2-R2-C5), commons
  references and other public-side files (type-only imports included, so the
  SDK re-exports the row types) (R4-M2). `scripts/shard-platform.mjs` follows: SF6 is reopened (below).
- **Custom side:** `runtime/`, any file whose closure reaches a non-SDK module, and any legacy file not yet sorted. A shared
  module used by exactly one shard counts toward that shard's custom side, so moving code into the SDK lowers nothing
  (B16; the kit itself dissolves into the SDK, G135).
- **Measure 1, public-SDK share** = public ÷ (public + custom) ≥ 80 %. Before `@wildshard/sdk` exists (SF8b) it prints
  0 %.
- **Measure 2, runtime ceiling** = `runtime/` lines ≤ 20 % of the shard's lines at the baseline (`lint/shard-platform.json`,
  `b96fed1a1`; the template 550, Thin Ice from its own first commit).
- **Milestone booleans** the gate prints: the template boots from its shardfile with no trusted chunk; its sim steps
  headless in Node; snapshot → restore → replay passes; per shard: grid-ready and
  compatible (headless + replay + ledger, A15).
- An 80/20 shard whose gameplay still partly lives in `runtime/` is **transitional**, and the gate says so; its
  remaining runtime is an open conversion item, never "compatible" by percentage alone (A15).
