That failure was an assertion mistake, not permission to accept arbitrary save
containers. The real `SaveStore.exportAll()` always includes the global document;
`SaveStore.savedDoc()` represents an absent document as `{ keys: {} }` without
writing it. Consequently an unused, storage-disabled store exports exactly
`{ global: { keys: {} } }`, rather than `{}`.

The new validator accepts only that exact envelope while the demo is running,
and accepts `null` only at the two genuine preboot observations. Every observed
raw localStorage and sessionStorage map must still be empty. Actual global,
profile and shard writes, world/quest/boss/reward/coin entries, reset metadata,
additional namespaces, malformed shapes and missing observations are refused.
There is no save-system change.
