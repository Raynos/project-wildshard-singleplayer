# Conch deterministic-shadow-path diagnostic plan

2026-10-19. Source audit only. No implementation, build, capture, quality score or appearance acceptance.

## Current recommendation after filterNode audit

**Do not implement the declarative split-rig candidate below.** It changes cascade resolution/count and effective radii, confounds the filter test and materially changes its budget. It is retained here only as the rejected compatibility analysis.

The existing `light.shadow.filterNode` property is honored by the actual WebGL node path and is not overwritten by EngineNodesHandler when defined. But changing it in the already-booted immutable host is **not supported by normal material rebuild alone** in this source version. There is a source-supported first-use route, conditional on a separately admitted diagnostic host fixture; it is not an in-place runtime A/B toggle. No implementation or build has occurred.

### Public property and stale-cache evidence

- `engineNodesHandler.ts:613–618` fills filterNode only when undefined, so explicitly selecting the existing exported `tentShadowFilter` survives light updates. No arbitrary replacement filter function is needed.
- `node_modules/three/examples/jsm/tsl/WebGLNodesHandler.js:65–83` uses GLSLNodeBuilder and lends classic WebGL shadow maps/depth textures to ShadowNode. `ShadowNode.js:475–489` selects `shadow.filterNode` before the renderer default and invokes it. Therefore this is not a WebGPU-only setting in this host.
- `LightsNode.js:236–286` reuses light nodes from a module WeakMap keyed by the light. `AnalyticLightNode.js:204–230` caches shadowColorNode/shadowNode. `ShadowNode.js:596–620` caches its generated `_node`, invalidating for shadow-map type changes, not filterNode identity. `LightsNode.js:147–173` likewise does not include filterNode in its light cache key.
- Engine material-version invalidation (`engineNodesHandler.ts:392–414`) recalculates material keys; material disposal (`793–808`) clears material entries/uniform groups, not those light-owned shadow nodes. Thus setting material.needsUpdate or recompiling/cloning its graph is not proof that a post-boot filter assignment becomes operative. Do not test with a flag-only claim.
- Do not clear private caches, call private `_reset`, alter the shadow-map type, replace the renderer/CSM/light, patch cache keys, or use light disposal as a reset workaround. ShadowNode disposal frees the map (`ShadowNode.js:739–761`) and DirectionalLight disposal disposes its LightShadow; that is outside a filter-only material rebuild.

## Rejected declarative route: finding

**The existing declarative API can select a deterministic tent shadow path, but cannot isolate only the filter on the current arena rig.** On the phone tier it requires `phoneSplits`, changes one 1024² cascade into three 2048² cascades, and overrides shadow radii. One candidate can test whether this existing supported shadow configuration removes the observed within-plane stippling while retaining received shadows. It cannot establish that stochastic sampling alone caused it.

The received-shadow diagnostic already established the conspicuous pattern's dependence on receiving shadows in these rest captures, with operative generated-shader evidence and byte-identical ON restorations. It did not distinguish sampling, self-shadow acne, depth conventions, normal bias, or toon amplification. This plan narrows the next experiment only to an existing shadow-path alternative; it does not revise that conclusion or the previous 59/100 and 64.75/100 assessments.

## Source-supported compatibility constraints

1. `src/practiceLevel.ts:13–26` selects `emptyLook(0.5)` directly. `src/game/shardfile/emptyLook.ts:6–23` supplies the existing clean chain/background/paused day clock, with no shadow style. Merely changing `sections/look/look.json` will not select arena shadows. `src/game/looks/toonLook.ts:64–67` forwards declarative shadows for the full toon world, but substituting that entire look would also change backdrop/fog/terrain handling and is outside this test.
2. `src/engine/render/look.ts:155–171` exposes `ShadowStyle`: `rig`, optional `filter: 'tent'`, `normalBias`, `radius`, and optional fade/texel-bias/depth16. `src/format/toonLook.ts:35–39` already validates the equivalent plain-JSON fields strictly. No schema extension is needed.
3. `src/engine/world/skyRig.ts:33–49,143–162` gates tent installation on BOTH `shadows.filter === 'tent'` and `rig.phone`. `rig: 'tier', filter: 'tent'` does not work. `phoneSplits` only sets `rig.phone` when the tier normally has one cascade. Desktop's three-cascade tier does not select this tent route even with the same data.
4. The current phone tier is one 1024² cascade to 80 m with 60 m caster margin (`src/engine/render/tiers.ts:4–7`). `phoneSplits` is three 2048² cascades ending at 7, 22 and 80 m, retaining the margin. Custom splitting replaces practical splitting, so shadow-camera fits, caster selection, light positions/targets and shadow matrices change. Camera-relative cascade overlap and weights change too. Do not assert identical full rendered light transforms between configurations.
5. `skyRig.ts:149,173–185` retains depth bias -0.00012 and allows normalBias .05, but tent mode unconditionally replaces requested radius with `SOFT_RADII`: [1.5, 1, 1] for this three-cascade rig (`shadowFilter.ts:20–22`). Radius 2 in the data therefore does NOT preserve effective radius. The near tent is 7×7 (16 hardware comparisons); later tents are 5×5 (9). Do not restore radius to 2 through a post-boot mutation or sweep it.
6. Omit fade, texelBias and depth16. That avoids extra temporal ghost lights, texel-fitted normal bias/far-cascade alternate updates, and the optional depth16 allocation route. CSM's existing `fade=true` remains on in both configurations (`skyRig.ts:151`); it is distinct from optional temporal shadow crossfading at lines 164–169.
7. `world/shadowFilter.ts:64–78,105–122` uses once-per-module installation flags and the existing classic chunk installer. `EngineNodesHandler.updateLights` (`render/nodes/engineNodesHandler.ts:610–623`) assigns the existing tent node only to cast-shadow lights whose filterNode is undefined; it does not replace an already installed node filter. Use fresh page contexts, not runtime toggling in a previously booted arena. The existing boot installer internally patches classic chunks as designed; this plan adds no patch and never calls it directly from a harness. If “no global shader patch” is intended to forbid even invoking this unchanged supported boot path, there is no compatible declarative candidate under that interpretation.
8. `render/nodes/tentShadowFilter.ts:26–70` is a deterministic texel-grid tent with receiver-plane slope compensation. `planeBiasShadowFilter.ts:25–40` is five Vogel taps rotated by screen-coordinate noise, also with receiver-plane compensation. They share `shadowDepthSample.ts:31–34`, including the existing fixedShadowSamples setting. Preserve and record that setting, not just material properties. The algorithms differ in tap placement, weighting, footprint and slope-compensation evaluation; even a hypothetical same-rig comparison would not isolate random rotation alone.
