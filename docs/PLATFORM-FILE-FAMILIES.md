# Registered streamed file families (G988 Z1)

`@wildshard/format/platformFileFamilies` registers a logical name pattern,
one defining format schema and its existing reader module. Registration
requires two real shard users and HOST-BAR's six tests, or Jake's explicit
host approval. A familiar prefix or a schema label alone grants no credit:
`validatePlatformFile(name, schemaSource, value)` runs the defining native
schema and the original consumer's semantic parser without rewriting the
value. `platformFileFamily` only matches the name and defining identity.

The nineteen Z1 grammars cover placement pages, scene recipes and buffers,
world-scene models, achievement counters, figure catalogues, quest page
composition, stalls, creature looks, posed libraries, stories, page life,
chapter directors, quest interactions and services, population directors,
panels, forest weather and adventure persistence. All have two or more
emitting shards; they account for exactly 98 files at the G988 baseline.
The runtime readers remain the existing data-driven game hosts, with view
readers labelled client-only by their owning APIs; the registry and native
admission themselves are renderer-free and install no services. No shard
identity, callback, new runtime owner or one-user grammar is admitted here.

`scripts/shard-platform-output.mjs` keeps verifying each named file's hash
and size, then excludes only admitted families from its custom count and
bytes. Unregistered named JSON and every `custom/` section still count.
`scripts/section-inventory.ts` reports these as `platform-file`, verifies
their full schema provenance against the defining catalogue, records the
registered reader, and follows emitted section routes transitively through
named documents. Its product summary's Custom column uses the same rule.
The files remain separate streamed payloads with their original bytes,
names, packing and runtime loading behavior.
