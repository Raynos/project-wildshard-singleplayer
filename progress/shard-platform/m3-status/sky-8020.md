# Sky Reach toward 80/20: inventory and move list (SF72, lane sf72-sky-gen, 2026-10-09)

Measured with `node scripts/shard-platform.mjs` (per-file classification copied from its `classify`), the method of
[signal-8020.md](signal-8020.md).

**At the start (HEAD `8f8d7c8d6`):** public 93 / custom 6,644 (1.4 %), runtime + trusted 1,245 / 1,377. Proofs: headless,
replay, ledger, gridReady and compatible true; boot false; transitional true.

80 % means custom ≤ public / 4. Of Sky's 6,737 code lines about 4,500 are view code (world 3,299, look 794, species rigs
361, the fan's model 145) and about 1,800 behaviour (runtime 1,188, quest 219, weapons 241, combat 20). As on Signal, **no
runtime move gets there**: the share moves when view code goes into `generators/` as a real offline bake (a generator is
public whatever it imports) and behaviour becomes declared rows.

## How the classifier reads Sky

- Public today: `behaviour/islet.as` 53, `generators/movers.ts` 17, and the pure data rows (`data/audio`, `brains`,
  `cues`, `state`, `storm`; `data/movers.ts` and the modules are generated and count 0).
- `data/items`, `data/quests`, `data/spawns`, `data/ledger`, `data/isletLift` and `shard.config.ts` are **custom** through
  `../layout` / `../strings` (root files, not a public folder) or `@wildshard/engine/*` type imports, exactly Signal's
  first trap. `layout.ts` 83 + `strings.ts` 30 → `data/` turns about 165 lines public.
- Every `world/` file a client module imports stays custom. A generator that the client also imports is fine for the
  generator (public) but a client import of a generator file is refused by the layout check, so constants the client
  needs (`WINCH_HOUSE`, `ROOST`, `DOCK`…) go to `data/` or `layout`.

## Ordered move list (line budget each frees)

1. **Promote Signal's baker into the SDK** (this lane): the instanced-kinds baker → `@wildshard/sdk/bake/kinds`, the
   baked-piece loader → a public client loader, Signal repointed byte-identical. No Sky lines move, but every Sky slice
   below uses it.
2. **Winch house + shack kit → `generators/`** (the first Sky slice): winchHouse 171 + the shack geometry kit ≈ 90 →
   public; the client keeps `shackMaterial` (the four procedural shaders) and reads `_SHK` from the GLB. ≈ +260 public.
3. **`layout.ts`, `strings.ts` → `data/`** (map input: rebake the map and the physics from the candidate): ≈ +165.
4. **Static props**: roost 79, bookStand 83, crown arena 149 (+ crownLayout), skyDock 83 (per-instance colour baked into
   a vertex colour or one kind per colour), knoll 38: ≈ +430. The `isle-cut` / `book` shader patches stay a client
   material keyed by the kind row.
5. **Bridges / decks as instanced kinds**: `plankBridge` and the span maths (shapes 204 in part, build's span colliders)
   → generator; the hover deck keeps its shared live material (the plugin brightens it), the fallen bridge stays a named
   node under its live pivot. ≈ +250.
6. **Isles, keels, meadow, dressing** (isle 169, meadow 259, dressing 245, skyIsleHd 183, fir 68, trees 40, distant 60,
   skyIsles 22): ≈ +1,050. Blocker: the playable isles draw on the session's `cosmetic` stream, which `crownStorm` reads
   after them; baking them needs the stream's draws replayed (or the storm reseeded, a visible change → Jake's call).
7. **Mill** (347; a live hub, a texture, three patches): the static body bakes, the hub stays live: ≈ +300.
8. **Species rigs, fan model, glove, keeper model** → generators: ≈ +560.
9. **Runtime rows** (keeper, boss-row runner for the Roc, quest + interaction rows, species numbers once the SDK publishes
   a data-only strike type): runtime −≈ 600, about half of it to public `data/`.
10. **SDK effect + look-family rows** (storm, wind, ray wake, cloud sea, sun glow, sky): custom −≈ 700.

What stays custom after all of it: manifest, budgets, the plugin, the Roc's storm script, the flock policy and thin client
materials: ≈ 900 lines against ≈ 5,000 public is ≈ 85 %. Moves 2–7 alone (≈ 2,450 lines) take Sky to ≈ 38 %.
