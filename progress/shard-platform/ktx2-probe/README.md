# ktx2-probe: never ship zeroed compressed textures (E435)

Code: `ae79fa22a` (`src/engine/render/ktx2Probe.ts`, the veto in `src/engine/boot/gpuFiles.ts` texModeWhy, the loader
config in `src/engine/core/ktx2.ts`, `__wildshard.textures()`, the perf panel's DEVICE lines).

## The probe

Once per page, before a texture mode resolves to KTX2: a throw-away WebGL2 context (lost straight after), one 8×8,
4-level texture per transcoder target uploaded the way three uploads (texStorage2D, then compressedTexSubImage2D per
level), every level sampled with textureLod into an RGBA8 target, one readPixels, each texel compared with the colour
its block encodes (±12). 12 formats: ASTC 4×4 linear / sRGB, ETC2 RGB / RGBA (EAC) linear / sRGB, BC7 linear / sRGB,
S3TC DXT1 / DXT5 linear / sRGB. ETC1 is not probed: three's texStorage2D allocation of it raises GL_INVALID_OPERATION on
WebGL2 in Chromium and WebKit alike, so the loader never targets it.

A failing family is dropped from the transcoder. When that leaves UASTC or ETC1S only the uncompressed RGBA32 target,
the page loads images and `texModeWhy` says so.
