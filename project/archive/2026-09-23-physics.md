Found while deriving the P0 walk route (today's `Player.ts` replayed in node on the real builders, fixed dt):

- **Today's controller is frame-rate dependent**: at a 50 ms frame the wreck-hold and shrine stairs jam (`collide()`
  runs on last frame's height before the ground snap); 1/30 … 1/144 pass. The fixed 60 Hz step removes this; P0's
  walk runs at 1× CPU (~60 fps) so its traces are comparable.
- **Shrine causeway front edge is 0.61 m above the terrain** — today you walk under the slab's edge and pop up once
  it's within 0.5 m. P4 gives it a tread (or a ramp lip); 0.35 m stays.
- **The terrain pokes up through the sea-cave floor** from z ≈ 19.6 and sits above the 2.2 m alcove floor from
  z ≈ 21.7 — today you walk the terrain, not the cave floor. P4 cuts the heightfield under the cave (a hole / lowered
  cells) so the cave trimesh is the floor.
- **Boat entry over the gunwale works by a hair** (the gunwale boxes are skipped while the feet are above 1.4 m);
  with Rapier it needs a gap or the jump — P4 decides with the clip.
- **The pier has no landing** — the deck ends 2.1 m above a sandbar under 0.9 m of sea; the route falls and wades.

So every stair becomes **real treads** (a cuboid per step, rise ≤ 0.35 m — autostep climbs them), never a ramp
collider; the treads are what the mesh already draws. That keeps the wreck hold climbable without loosening 40°.

## Architecture (the contract every phase builds on)

**`src/physics/`** — the only module that imports Rapier:

| File | Owns |
|---|---|
| `Physics.ts` | `initPhysics()` (async, once, at boot), the `World`, a **fixed 60 Hz step** with an accumulator (max 3 substeps, so a long frame-gate pause resumes without a spiral; render interpolates dynamic bodies), `dispose()` on shard change |
| `groups.ts` | collision groups: `WORLD` · `PLAYER` · `CREATURE` · `HITBOX` · `PROJECTILE` · `ITEM` · `DEBRIS` · `SENSOR` and who hits whom (debris never hits the player; projectiles hit world + hitboxes; creatures hit world + player + each other) |
| `shapes.ts` | builders: `heightfieldFromBaked(grid)`, `cuboid`, `capsule`, `convexHull(geometry)`, `trimesh(geometry)`, `treads(stair)`, and `fromMesh(object3d, kind)` for the procedural builders |
| `colliders/<structure>.ts` | one collider file per world builder, reading the **anchors / dimensions the builder exports** (not its meshes' internals) — so the model agent can keep rebuilding a structure and only an anchor rename reaches physics |
| `surface.ts` | a `Surface` tag on every collider — **reuses `src/audio/Surface.ts`'s union** (`sand · wetSand · grass · rock · planks · stone · water`) plus `flesh` · `metal` · `wood`; drives bolt sticking, impact FX and footsteps (`SurfaceMap` becomes a ray down + the tag, terrain classification kept) |
| `query.ts` | the game's one query API: `castRay`, `castShape` (sword arc, bolts), `overlap` (interact, blast, plates), `lineOfSight`, each with a group mask, returning `{ point, normal, distance, surface, owner }` — `owner` is the animal / door / pickup / plate behind the collider |
| `Character.ts` | the player's `KinematicCharacterController` capsule (autostep, snap-to-ground, slope limits, platform carry, dash as a desired translation that ends on a hit) |
| `debug.ts` | `?physics=debug` draws `world.debugRender()` lines — the authoring tool for every collider below |

Rules:

- **Game feel stays ours; collision is Rapier's.** Hover spring, swim buoyancy (on the Gerstner swell), wade
  hysteresis, double jump, dodge / lunge speeds, landing impulse, stagger curves, hit-stop stay game code on top of
  the controller's move. Nothing re-hand-rolls a collision test outside `src/physics/`.
- **Time:** the accumulator is fed the **scaled** `dt` the loop already hands every updater, so hit-stop
  (`Game.hitStop`, ×0.04) freezes bodies with the world; debris / FX keep `worldTime.realDt`. The frame gate
  (rotate gate, feedback composer) skips the step for free.
- **Explore mode keeps stepping** (animals keep their ambient AI there) with the parked player body disabled;
  FreeCam never collides.
- **`heightAt()` stays for placement and rendering** (trees, grass, props, decals). It stops being physics.
- **Water isn't a fluid.** `waterLevel` / `pondMask` / `waveHeight` keep driving swim / wade; floating items and
  the boat get a small buoyancy from them.
- **`player.colliders` goes away in P4** — its last readers (`Ocean.foamAround`, `MeleeSweep`, `Adventure.floorAt`,
  `SurfaceMap`) move to `query.ts` in the phase that deletes their source.
- **Collider authoring, cheapest first:** a primitive where the shape is a box / capsule / ball; a convex hull
  where it's a solid rock or crate; stairs as treads; a trimesh only where you walk *inside or over* irregular
  geometry (the heeled wreck hull and decks, the sea cave, the shrine terraces). Built in `slicer()` slices like
  the meshes; if a shard's collider build busts the 100 ms long-task budget, P9 bakes them into
  `public/assets/baked/<slug>/colliders.bin`.
- **Loading:** the plain `.wasm` (not the base64 `-compat` build: +33 % bytes and a blocking decode), streamed with
  `WebAssembly.instantiateStreaming` during the title screen, `application/wasm` in `vercel.json`, in the
  service worker's asset index and the boot plan's byte counter; SIMD build only (the iOS app targets 17.0).
- **Single-threaded forever**: Capacitor never gets `crossOriginIsolated` (iOS `capacitor://`, Android WebView),
  so no WASM threads and no physics worker — the controller needs synchronous answers each frame anyway.

## Why Rapier (E20 research, 2026-09-22)

| | Rapier 0.20 | crashcat 0.0.5 | Jolt 1.1 |
|---|---|---|---|
| wire | ~560 KB br | ~46 KB | ~880 KB |
| controller | built-in KCC (autostep, snap, slopes, push) | Jolt-style KCC | `CharacterVirtual` |
| heightfield | yes | no (trimesh) | yes |
| types / memory | strict, no `any`, GC-friendly handles | native TS | some `any`, manual `destroy()` |
| maturity | years in production, very active (pushed 2026-09-20) | pre-1.0, one maintainer | mature C++, small JS port |

Havok (Babylon-first), PhysX (1.6 MB), Ammo (dead since 2016), cannon-es (no releases since 2022), Oimo — out.
Known Rapier risk: the KCC can dip into a **vertically moving** platform ([#488](https://github.com/dimforge/rapier/issues/488))
— the boat now heaves, pitches and rolls on the swell, so P4 carries the player with the boat's full pose delta
explicitly (and the bridge the same way if A7's sway lands).

**From the trials-gauntlet** (`~/projects/game-demos/trials-gauntlet-demo/docs/plans/USE_A_REAL_PHYSICS_LIBRARY.md`,
parked, never started; a 2D bike game, so its Rapier-2D / Planck picks and its replay-determinism contract don't
port). Kept: count WASM bytes and startup separately; async init at boot, never inside a tick; the library owns
collision, the game owns feel; judge by **played clips**, not stills. Dropped by the user: the side-by-side
switch — P0's baseline is the control instead.

## Risks

1. **WASM compile on an iPhone** — unmeasured anywhere; P1 measures it first on the headless phone tier (4× CPU), before anything else depends on it; the real iPhone sees it only after the merge.
2. **Feel regressions** in the walk / jump / dodge / lunge / hover / swim loop once the controller changes — P0 clips + numbers are the guard; the user's thumbs are the judge.
3. **Frame time on the phone** — PLAY-PERF's iPhone reading is still unconfirmed (E4) and the physics gates are headless best guesses; P6 (creatures), P6b (paths) and P8 (ragdolls) are the expensive phases. The real iPhone reading comes after the merge — if it misses, that's a follow-up ask.
4. **Merge drift** — the branch lives for weeks while five remaster agents rewrite the same builders, `Sword.ts`, `Animal*.ts`, `Interactables.ts`. Mitigation: §Lanes (colliders read exported anchors), a rebase at every phase start, and P4's colliders re-authored for whatever the model agent rebuilds after them.
5. **Moving surfaces** — the boat (heave + pitch + roll, #488) and, if A7 lands, the swaying bridge and zipline.
6. **Stricter climbing (0.35 m / 40°) can cut today's routes** — `groundAt` steps 0.5 m today; dunes, crag paths, the wreck's 44° hold stair (→ treads) and porch steps may need treads or ramps; P2 finds them, P3 / P4 fix them.
7. **Hit-stop and the fixed step** — a 60 Hz accumulator on a ×0.04 time scale steps ~once per 25 frames; lunge / knockback started in the hit frame must not jump. P2 / P6 clips check it.
